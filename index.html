About

Where infrastructure, automation, and delivery meet.

I work at the intersection of development and operations — designing deployment workflows, containerizing applications, and provisioning cloud infrastructure that is repeatable and easy to reason about. My approach starts with a simple question: how do we ship this safely, and how do we know when it breaks.

I'm comfortable across the delivery lifecycle: writing CI/CD pipelines in GitHub Actions and Jenkins, containerizing services with Docker, managing AWS resources with IAM, EC2, and S3, and scripting automation with Bash. I care about reducing manual steps, tightening feedback loops, and building systems that fail loudly instead of silently.

I collaborate naturally with developers — I've built the applications I deploy, which means I design infrastructure with the engineer's workflow in mind, not against it.

URL Shortener — Containerized Deployment with CI/CD on AWS

Deployed

A Spring Boot + MySQL URL-shortening service, built to practice the full delivery path: containerize the app, automate the pipeline, and run it on real cloud infrastructure rather than a local machine.

Key work

  • Built the service with Base62 encoding and packaged it using a multi-stage Docker build to minimize image size.
  • Set up a GitHub Actions pipeline that tests, builds, and pushes Docker images to GitHub Container Registry (GHCR) on every push to main.
  • Deployed to an AWS EC2 instance with Docker Compose, using environment-based secrets and security groups scoped for controlled network access.

Log Watcher + Slack Alert Script

Running

Manual log-checking doesn't scale. This script watches application logs in real time and pushes an alert the moment something looks wrong, cutting the time between failure and awareness.

Key work

  • Built a Bash script that tails application logs and detects error/warning patterns using regex-based matching.
  • Integrated the Slack webhook API to trigger automated alerts once error thresholds are breached.
  • Deployed the watcher as a persistent systemd service, so it keeps running and restarts automatically on failure.
